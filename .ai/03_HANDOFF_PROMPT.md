【系統接力指令：SSSM 短上下文與多 LLM 協作模式（arXiv:2611.05306＋Modern Web Guidance 1.0）】
你現在接手 Shainy Hsu 登山工具生態系（步程試算 與 實走紀錄分析／路線剖面比較／上山籌碼評估）的開發節點，各工具版本以 01_CURRENT_STATE.md 為準。本專案採用「語義狀態空間模型（SSSM）與單一動作壓縮（Single-Action Compaction, SAC）」協議，維持 16K–32K 短上下文並防止失憶。請用繁體中文、台灣用語回覆，並嚴格遵守以下六項鐵律：

1. 單一動作與禁止重寫：這是已迭代上百版的成熟專案，請尊重現有架構、單檔純前端結構與變數命名。每次對話只解決 01 的「當前唯一原子任務」，只輸出最小必要修改（diff 或完整目標函數），嚴禁整檔重寫。
2. 黑盒與選擇性讀取：除非我提供或要求，不展開 00 以外的模組細節。需要看其他函數時，直接告訴我「函數名稱」（以 00 索引為準），我局部貼上；不要求整檔傾倒。能直接存取 repo 的代理：用 grep 定位，每次讀 ≤150 行。
3. 事實與假設分離：01 第 3 節「未驗證想法」不得當成已實作功能；你提出的新演算法或結構修改，在我實測確認前一律標記 [Unverified]。
4. 避開死胡同：動手前先核對 02 的 Dead Ends，不提出已被驗證失敗的方案。
5. Modern Web Guidance 1.0：UI 互動、版面與離線儲存優先用瀏覽器原生 Web API（`<dialog>`、Popover API、CSS Grid、IndexedDB／OPFS），Baseline 目標為 Baseline Widely Available，拒絕肥大依賴。
6. 結尾交接簡報：每次回答最後不寫回顧流水帳，改附一份不超過 180 字、供下一個 LLM 接力的簡報，格式如下，方便我直接覆蓋回 .ai/ 檔案：

【SSSM 狀態更新簡報】
- Applied（已改動）：改了哪個檔案的哪個函數
- Status（事實狀態）：Verified 或 Unverified；是否達成 Done Criteria
- Dead Ends（新增踩坑）：本次發現走不通的做法；無則填「無」
- Next Action（下一步唯一動作）：下一個 LLM 接手後的第一個具體動作
